LeetCode 146 · Hashmap + Doubly Linked List

寄物間快取

一個寄物間只有 N 個掛勾。滿了要丟東西，丟的是「最久沒人碰的」，不是「放最早的」。你要讓「拿」「放」都在 O(1) 時間完成。

①白話：這題在幹嘛

你要做一個有大小限制的置物櫃。放滿了，新東西進來就要丟一個舊的——丟的規則是「最久沒被碰過」，不是「放進去最久」。每次你去拿或放一個東西，那個東西就變成「剛剛用過」，暫時安全。

②這是什麼型，秒認信號

  • 01題目要你「design a data structure」，不是寫一個 function
  • 02同時出現 capacity 限制 + get/put 都要求 O(1)
  • 03需要同時記兩件事：「這個 key 現在的值」和「哪個 key 最久沒被碰」

單獨一個 hashmap 只能秒查值，不記順序。單獨一個 array／list 好記順序，但插入或刪除中間那個要搬東西，O(n)。這兩題各自都有解，但「兩個都要」，才是這個型的訊號：hashmap 負責給位置的直接指標，doubly linked list 拿著那個指標做 O(1) 插拔。

③暴力解，為什麼慢

最直覺的做法：一個 dict 存值，外加一個 list 存「使用順序」，最久沒碰的排最前面。get/put 命中時，把該 key 從 list 裡挖出來，塞到 list 尾端（代表「剛剛用過」）。

order = [1, 3, 2] — 要把 key=2 挪到尾端，得先找到它

list.remove(2) 要從頭一個一個比對，掃了 2 步才找到位置。

問題就在「找出來刪掉」這一步：list.remove(key) 得從頭掃過去才能找到那個 key 的位置，這是 O(n)。dict 明明已經用 O(1) 查到了值，但「它在 list 的哪個位置」這個情報，dict 完全不知道——list 只好重新從頭找一次。这就是浪費的免費情報：早就查到手的位置，沒有存下來，白白丟掉重找。每次 get/put 都要付一次 O(n)，呼叫次數上看 2×10⁵，總成本 O(n²)，會超時。

④做法一步一步

優化版：把 dict 改成存「指標」，不是存「值」。指標直接指到掛桿上的那個掛勾，不用再找。掛桿本身是 doubly linked list——每個掛勾知道左右鄰居是誰，所以「把某個掛勾抽出來」只要跟它自己的左右鄰居打招呼就好，跟其他掛勾無關，O(1)。掛桿兩端各釘一根固定柱子（sentinel），本身不掛外套，只是邊界，讓「這是第一個/最後一個掛勾」不用另外判斷。

兩個原子動作，之後所有操作都只是這兩個動作的組合：

  • 拔（remove）：把某個掛勾從目前位置抽走，讓它左右的鄰居直接牽手
  • 插到最前面（insert_front）：把某個掛勾插到最靠門口（MRU）那端

get 命中 = 拔 + 插到最前面（順便回傳值）。put 命中舊 key = 改值 + 拔 + 插到最前面。put 新 key = 新掛勾插到最前面；如果超過 capacity，把最裡面（LRU 端）那個掛勾拔掉，順手把它的號碼牌從號碼本撕掉。

完整 code + 逐行解釋 
class Node:
    def __init__(self, key=0, val=0):
        self.key, self.val = key, val
        self.prev = self.next = None


class LRUCache:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.map = {}                  # key -> Node，直接指標，不用找
        self.head, self.tail = Node(), Node()   # 兩個 sentinel，不裝真資料
        self.head.next = self.tail
        self.tail.prev = self.head

    def _remove(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _insert_front(self, node):
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key: int) -> int:
        if key not in self.map:
            return -1
        node = self.map[key]
        self._remove(node)
        self._insert_front(node)
        return node.val

    def put(self, key: int, value: int) -> None:
        if key in self.map:
            node = self.map[key]
            node.val = value
            self._remove(node)
            self._insert_front(node)
            return
        node = Node(key, value)
        self.map[key] = node
        self._insert_front(node)
        if len(self.map) > self.capacity:
            lru = self.tail.prev
            self._remove(lru)
            del self.map[lru.key]

變數在幹什麼

變數角色
self.mapkey → Node 的直接指標，取代暴力解裡「找位置」那一步
self.head / self.tail兩個永遠存在的 sentinel，卡住鏈的兩端，讓「是不是第一/最後一個」不用另外判斷
node.prev / node.nextdoubly linked list 的雙向指標，讓 _remove 不用從頭找鄰居

指標重接的順序會咬人

_remove 和 _insert_front 裡，一定要先讀出舊的 prev/next，再覆寫指標。順序顛倒的話，你會先把某個指標蓋掉，後面要用的那個舊鄰居就已經找不到了——鏈斷掉但不會報錯，最貴的那種 bug。這招你在 #21 的 dummy node 已經踩過一次同樣的坑。

口訣 + 模板
LRU = 服務台號碼本（hashmap）記位址 + 掛衣桿（doubly linked list）記順序。碰一次就「拔下來、插到最前面」，滿了就「砍掛桿最裡面那個，順手把它的號碼牌從號碼本撕掉」。get/put 都是 O(1) 時間，O(capacity) 空間。

兩個 sentinel 打掉的邊界 special case，跟 #21 的 dummy node 是同一招：先固定一個不會消失的柱子，鏈永遠有頭有尾可以掛，不用判斷「這是不是第一個」。

class Node:
    def __init__(self, key=0, val=0):
        self.key, self.val, self.prev, self.next = key, val, None, None

class LRUCache:
    def __init__(self, capacity):
        self.capacity, self.map = capacity, {}
        self.head, self.tail = Node(), Node()
        self.head.next, self.tail.prev = self.tail, self.head

    def _remove(self, n):
        n.prev.next, n.next.prev = n.next, n.prev

    def _insert_front(self, n):
        n.next, n.prev = self.head.next, self.head
        self.head.next.prev, self.head.next = n, n

    def get(self, key):
        if key not in self.map: return -1
        n = self.map[key]; self._remove(n); self._insert_front(n)
        return n.val

    def put(self, key, value):
        if key in self.map:
            n = self.map[key]; n.val = value
            self._remove(n); self._insert_front(n); return
        n = Node(key, value); self.map[key] = n; self._insert_front(n)
        if len(self.map) > self.capacity:
            lru = self.tail.prev; self._remove(lru); del self.map[lru.key]
