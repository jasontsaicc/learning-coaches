LeetCode #543 · Tree · 龜模式

路在我這裡轉彎

Diameter of Binary Tree。#104 每個 node 只算一個數字。這題開始，每個 node 身上同時有兩個數字，而且它們長得很像、意思完全不同。

01這題在幹嘛

這棵樹上，任意挑兩個 node 連成一條路。最長的那條有幾條邊？

題目原文的關鍵字：the longest path between any two nodes，還有一句 this path may or may not pass through the root。出題者在明講：別只算 root。

第一號坑：length 數的是「邊」，不是「node」

一顆孤零零的 node，diameter 是 0，不是 1。兩個 node 是 1，不是 2。面試時第一句就要跟面試官確認這件事，因為 #104 剛好數的是 node，兩題差一格最容易翻車。

02這是什麼型，怎麼秒認

型別：一趟 DFS，順路記帳（tree DP 的入門款）。三個秒認信號：

  • 1
    題目說「任兩個 node 之間」 → 答案可能長在任何一個 node 身上，不只 root。
  • 2
    題目主動提醒「不一定經過 root」 → 這是出題者在戳你最可能犯的錯。
  • 3
    樹 + 求一個最大值 → 雙軌：遞迴回傳值餵上級，全域變數收答案。

秒認之後要馬上想到的下一句：「路徑一定有一個最高點。」每條路都是先往上爬、在某個 node 轉彎、再往下走。那個轉彎點是唯一的。所以只要對每個 node 都問一次「路在你這裡轉彎的話多長」，就不會漏掉任何一條路。

03暴力法長怎樣、為什麼慢

照著上面那句話直接翻成 code：每個 node 都當一次轉彎點，左右各叫一次 #104 的 maxDepth。

# 暴力:每個 node 都當一次「最高點」
ans = 0
for X in 每個 node:
    ans = max(ans, maxDepth(X.left) + maxDepth(X.right))

它是對的，只是慢。慢在同一塊子樹被重複走了很多次：

當你在算maxDepth 走過哪些 node
node 12, 4, 5, 3
node 24, 5 ← 又走一次
node 4（葉子）

外層 n 個 node，內層每次 O(n) → O(n²)。

浪費掉的免費情報

maxDepth(X) 在 return 之前那一瞬間，它手上同時握著 L 和 R。也就是說，它當下就已經知道「穿過 X 的最長路 = L + R」了 —— 然後它把這個情報丟掉，等外層迴圈再花 O(n) 把它算回來。

O(n²) → O(n) 的全部內容，就是「順手把它記下來」。

04每個 node 身上有兩個數字（無 code，純圖）

這一節是整題的心臟。這兩個數字搞混 = 這題寫不出來。

軌道 A · 往上交　return 給呼叫我的那一張紙。上級要拿去繼續往下走。
軌道 B · 記帳本　寫進 self.ans。這是答案本人，不交給任何人。

軌道 A只能挑一邊

return max(L, R) + 1

= max(2,1)+1 = 3。這行跟 #104 一個字都沒改。

軌道 B兩邊都吃

self.ans = max(self.ans, L + R)

= 2 + 1 = 3 條邊。不用 +1，也不用 −1。

往上交要挑一邊（max），記帳本可以吃兩邊（+）。

為什麼 L + R 剛好就是邊數？

L = 2 的意思是「左邊最長往下有 2 個 node」。從 me 走到那個最深的子孫，正好跨 2 條邊。右邊同理跨 1 條。合起來 3 條。

單位在這裡自動換掉了：回傳值是 node 數，相加之後變成 edge 數。這種地方是 off-by-one 的高發區，面試時要主動講出來，面試官會加分。

最後一個轉折：depth(root) 的回傳值沒人要

整棵樹跑完之後，最外面那個 depth(root) 會吐出一個數字。那個數字是樹的最大深度，不是答案。直接丟掉。答案在帳本裡。

return depth(root)　→　回到 #104，答案全部偏小
depth(root)　然後　return self.ans

第 04 格是整題最容易騙過自己的地方

那裡「記帳」算出 2，「往上交」也算出 2。你會覺得「啊那不是同一個東西嗎」。不是。看第 06 格：記帳算出 3（2+1），往上交也算出 3（max(2,1)+1），數字又撞在一起。

兩個數字差多少，其實有公式。把它們相減：

記帳 − 往上交
= (L + R) − (max(L,R) + 1)
= min(L,R) − 1        # 因為 L+R = max(L,R) + min(L,R)

所以它們只有在 min(L,R) == 1 的時候才會剛好相等。第 04 和第 06 格都踩中這個巧合（min(1,1)=1、min(2,1)=1），所以你看不出差別。

看第一列：連葉子都已經分岔了（記帳 0、往上交 1）。它們從頭到尾就不是同一件事，只是這棵小樹上撞了兩次同值。

完整 code 加逐行解釋自己寫完再展開 
class Solution:
    def diameterOfBinaryTree(self, root):
        self.ans = 0                            # 帳本,從 0 開始

        def depth(node):
            if not node:                        # 煞車:空的往下 0 格
                return 0
            L = depth(node.left)                # 委派左邊
            R = depth(node.right)               # 委派右邊
            self.ans = max(self.ans, L + R)     # ★ 軌道 B:記帳
            return max(L, R) + 1                # 軌道 A:往上交 (= #104)

        depth(root)                             # 跑完整棵樹,回傳值故意不接
        return self.ans                         # 答案在帳本裡
行做什麼拿掉會怎樣
self.ans = 0開一個不會被撕掉的帳本AttributeError
if not node: return 0煞車。回 0 因為空子樹往下 0 格無限遞迴 → RecursionError
L = depth(node.left)委派左邊，等它跑完算不出自己這層
return max(L,R)+1軌道 A。上級只能走我一邊上級收到 None
self.ans = max(...)軌道 B。整題唯一的新增行退化成 #104
return self.ans交帳本，不是交回傳值答案變成最大深度

複雜度

Time O(n)：每個 node 進去一次、出來一次，記帳是 O(1)。
Space O(h)：h 是樹高。平衡樹 O(log n)，退化成一條鏈就是 O(n)。

題目說 node 數可到 10⁴。如果測資是一條 10⁴ 長的斜鏈，Python 預設 recursion limit 是 1000，會爆 RecursionError。面試講到這裡就夠加分了；真要解就 sys.setrecursionlimit 或改成 iterative post-order。

口訣加模板可以直接搬到下一題

往上交要挑一邊（max），記帳本可以吃兩邊（+）。

雙軌 tree DP 通用模板

def solve(self, root):
    self.ans = 初始值
    def dfs(node):
        if not node: return 中性值
        L = dfs(node.left)
        R = dfs(node.right)
        self.ans = max(self.ans, 「以 node 為最高點」的值)   # 軌道 B
        return 「能往上延伸」的值                        # 軌道 A
    dfs(root)
    return self.ans

整個系列只換那兩行：

題軌道 B（記帳）軌道 A（往上交）

#124 Max Path Sumnode.val + L + Rnode.val + max(L,R,0)
#110 Balanced Treeabs(L − R) ≤ 1 ?max(L,R) + 1
#104 Max Depth（沒有軌道 B）max(L,R) + 1

看出來了嗎：#104 就是「只有軌道 A」的特例。所以 #543 不是新題型，是同一個模板長出第二條軌道。

MOVE 2暴力解 20 秒 + 指出浪費了什麼

說"The brute force is: every path has exactly one highest node where it turns. So for each node, compute maxDepth(left) + maxDepth(right) and take the max. That's correct but O(n²), because maxDepth re-walks the same subtrees over and over."
想「every path has exactly one turning point」這句話是整題的 insight。先在暴力解講出來，後面優化就順了。

MOVE 3講 invariant

說"Here's the key: when depth(node) is about to return, it already holds both L and R. At that exact moment it knows the best path turning at this node — it's L + R. So I don't need a second pass. One DFS, and I record the answer on the way back up."
想這是把 O(n²) 砍成 O(n) 的唯一一句話。面試官在等的就是這句。

MOVE 4關鍵手法 + 換掉了什麼

說"Each node produces two different numbers. The one I return is max(L,R)+1 — the parent can only extend through one side. The one I record is L+R — this path turns here, so it uses both sides. I'm trading one extra variable of state for a whole factor of n."
想「two different numbers」講清楚，面試官就知道你不是背的。

MOVE 5複雜度講在寫 code 之前

說"Time is O(n) — every node visited once. Space is O(h) for the call stack, which is O(log n) balanced but O(n) if the tree is skewed. Sound reasonable?"
想先設計、先對齊，再動手。"Sound reasonable?" 是換取修正的最便宜方式。

MOVE 6code 分 3 段寫

說（第 1 段）"I'll keep the running answer on the instance so it survives the whole traversal."
寫self.ans = 0
說（第 2 段）"Base case returns 0 — an empty subtree goes down zero levels. Then I recurse both sides and wait for both."

MOVE 7主動 dry run（用 Move 1 的例子）

說"Let me trace it. depth(4) and depth(5) both return 1 and record 0. At node 2, L and R are both 1, so I record 1+1 = 2 and return 2. At node 3 I record 0 and return 1. At the root, L is 2 and R is 1, so I record 2+1 = 3. Answer 3, matching the picture."

MOVE 8主動掃 edge case

說"Single node: both children are None, so I record 0+0 = 0 — correct, no edges. Empty tree: the base case returns 0 immediately and self.ans stays 0. And the case the problem warns about — diameter not through the root — is handled automatically, because I record at every node, not just the root."
想最後一句是關鍵：點名「哪個設計自動答對了哪個 case」，這比列 case 清單有價值得多。

說"Two follow-ups worth flagging. If the tree can be 10⁴ deep and skewed, Python's default recursion limit will blow up — I'd convert this to an iterative post-order with an explicit stack. ② self.ans 為什麼不用宣告？nonlocal 又是什麼？

判準（你 2026-09-07 自己問出來的那條）　看 = 左邊有沒有 . 或 []。
✗ ans = ans + 1　左邊是光禿禿的名字 → 觸發「local 蓋章」→ UnboundLocalError。
✓ self.ans = ...　左邊有 .，這是 setattr，不是名字賦值。self 只被讀，所以不用宣告。
✓ nonlocal ans　明講「我要改外層那個」，Python 配一個 closure cell 給你。

關鍵是這是編譯期決定的，不是執行期：

# 編譯 bump 的時候(一行都還沒跑)

    ans = ans + 1
