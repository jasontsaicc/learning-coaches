剪下來像不像

Subtree of Another Tree。大樹裡有沒有一塊,整塊剪下來會跟小樹一模一樣。

01這題在幹嘛

給你兩棵樹:一棵大的 root,一棵小的 subRoot。問大樹裡面有沒有一塊,整塊剪下來會跟小樹長得一模一樣。

藍色那一塊從大樹的 4 整塊剪下來,跟小樹完全一致 → 答案 True

「整塊」是這題的關鍵字

不能只剪一半。大樹的 4 底下有 1 也有 2,剪下來就一定是 4(1,2)。小樹如果只有 4(1),那就不算。

大樹有 2,小樹那格是空的。多一顆也算不一樣 → 答案 False

02這是什麼型,怎麼秒認

型:DFS 遞迴,兩層。外層走遍大樹,內層比對兩棵樹。

三個秒認信號

  1. 題目給你兩棵樹 → 幾乎一定需要一個「比兩棵樹」的 helper。
  2. 題目出現 subtree / 藏在 / 包含 → 不知道從哪開始比,所以每個 node 都要當一次起點。
  3. 題目寫 same structure and node values → 這句話本身就是 #100 Same Tree,直接搬過來用。
這題的價值不在寫,在拆。看穿「#572 = 一層 walker + 一顆 #100」比手速重要得多。NeetCode 的 tree 區段一路都在練這個:#104 高度 → #543 借高度 → #110 借高度 → #572 借 #100。

03最直覺的想法為什麼不夠

看到兩棵樹,第一個反應通常是:那就 isSameTree(root, subRoot) 比一次不就好了?

跑跑看會發生這件事:

PASS   root=[3,4,5,1,2]   sub=[3,4,5,1,2]     ← 唯一過的一筆
FAIL   root=[3,4,5,1,2]   sub=[4,1,2]
FAIL   root=[1,2,3]       sub=[2]
FAIL   ... 其他 6 筆全掛

唯一過的那筆,小樹跟大樹一模一樣,也就是「站在第一站就中了」。其他每一筆答案都藏在更下面。

比一次只能驗證一個位置。小樹可能掛在大樹的任何一個 node 底下,所以要把每個 node 都當一次起點,各比一次。

那更笨的做法長怎樣?

把大樹的每一棵子樹都印成字串(serialize),再跟小樹的字串一個一個比。這反而比較慢,因為光是印字串就要走完整棵子樹,而且字串比對本身還有成本。

所以 O(m × n) 的「每站問一次」就是這題的標準答案,不是偷懶版。真正的升級版在最後一節(follow-up)。

完整 code 加逐行解釋

外層:走路的

def isSubtree(self, root, subRoot):
    if not root:
        return False
    if self.isSameTree(root, subRoot):
        return True
    return self.isSubtree(root.left, subRoot) or self.isSubtree(root.right, subRoot)
行在做什麼為什麼一定要有
if not root:煞車。走到空的大樹了沒有它,下一行 root.left 會對 None 取屬性 → AttributeError
return False交回「這條路沒找到」函式契約是 bool。base case 要交回同一種型別,不能交 None 或 0
if self.isSameTree(…)站在這一站問一次:從我這裡剪下來,整棵像不像這是整題唯一「做事」的那一行。其他都是走路
return True像的話,整個函式立刻收工early exit。剩下的 node 完全不用走
return … or …委派:左邊走一次、右邊走一次root.left 讓問題變小,這是遞迴會停下來的原因。subRoot 全程不變

內層:比對的(這就是 #100,直接搬)

def isSameTree(self, p, q):
    if not p and not q:
        return True
    if not p or not q:
        return False
    if p.val != q.val:
        return False
    return self.isSameTree(p.left, q.left) and self.isSameTree(p.right, q.right)
行在做什麼
not p and not q兩邊都空 → 一樣(都沒東西也是一種一樣)
not p or not q只有一邊空 → 不一樣。這一行接住「多一顆 / 少一顆」
p.val != q.val值不同 → 不一樣。放在委派前面是為了 early exit
… and …左右都要一樣才算一樣
#100 為什麼是前序,#110 為什麼是後序?
判準只有一句:這件事需不需要等小孩的答案?
p.val != q.val 不需要 → 放委派前面(前序),還能提早收工。
abs(L - R) 非得等 L 和 R 回來 → 只能放委派後面(後序)。

複雜度

  • Time O(m × n):大樹 m 個 node,每一站最壞要把小樹 n 個 node 整個比一遍。
  • Space O(h):遞迴堆疊的深度,h 是大樹的高度。斜樹最壞 O(m)。

完整答題示範,也是英文 shadowing 素材。每個 move 三格:說(嘴巴講的,可以直接背)、想(為什麼這樣講)、寫(白板上長出什麼)。

MOVE 0 · 先問 constraint,手不碰白板

"Before I jump in, let me clarify a few things. First, can subRoot be empty, or is it guaranteed to have at least one node? Second, how large can these trees get? And third, can node values repeat inside the tree?"

想:第三個問題是這題的關鍵。值會重複代表「找到一個值相同的 node」不等於「找到答案」,必須整棵比對。問這一題等於告訴面試官你已經看穿陷阱。

寫:什麼都不寫。

MOVE 1 · 重述題目,自己舉例

"So I need to find a node in the big tree where the entire subtree rooted at that node is identical to subRoot. Not a partial match. Let me draw a case I'll come back to later."

想:"entire" 這個字要重讀。後面 dry run 直接指這張圖,省時間。

root:  3            subRoot:  4
      / \                    / \
     4   5                  1   2
    / \
   1   2

MOVE 2 · 暴力解 20 秒,指出浪費了什麼

"The naive read is to compare the two roots once. But that only catches the case where subRoot sits at the very top. The match can live anywhere, so a single comparison throws away every other candidate position."

想:這句話證明你比較過,不是背下來的。面試官筆記本上記的是「有 consider alternatives」。

寫:在圖上圈出 3、4、5、1、2 五個候選起點。

MOVE 3 · 講出 invariant

"Here's the invariant. isSubtree(node) is true if and only if either the subtree rooted at node matches subRoot exactly, or the answer lives in node's left or right subtree. Every node gets tested exactly once as a starting point, so I can't miss a match."

想:"if and only if" 是 invariant 的標準句型,把正確性推理講死。"exactly once" 是覆蓋性證明。

isSubtree(node) = isSameTree(node, subRoot)
                  or isSubtree(node.left,  subRoot)
                  or isSubtree(node.right, subRoot)

MOVE 4 · 關鍵手法,以及換掉了什麼

"I'll split this into two functions. The outer one walks the big tree. The inner one compares two trees node by node, which is exactly the Same Tree problem. I'm trading time for clarity here: re-comparing from scratch at every station costs me O(m times n), but each function does one job and the inner one I already know is correct."

想:「我把它拆成兩個函式,內層是我剛才寫的那題」是很值錢的一個 move。面試官聽到的是「會組裝已知零件」,不是「背了一題」。

寫:畫兩個方框,外層套內層,箭頭標 "calls at every node"。

MOVE 5 · 複雜度講在寫 code 之前

"Time is O(m times n) in the worst case: m nodes in the big tree, and each one can trigger a comparison that walks up to n nodes. Space is O(h) for the recursion stack, which degrades to O(m) on a skewed tree. Sound reasonable?"

想:先設計再實作。結尾那句 "Sound reasonable?" 是跟面試官對齊,一定要問,不要自己埋頭寫下去。

寫:Time O(m·n) / Space O(h) 寫在白板角落。

MOVE 6 · code 分 3 段寫,每段講一句

"First the guard. If I've walked off the end of the big tree, there's nothing here to match, so I return false."

def isSubtree(self, root, subRoot):
    if not root:
        return False

"Then the check at this station. I ask whether the subtree rooted right here is identical to subRoot. If it is, I'm done, I bail out immediately."

    if self.isSameTree(root, subRoot):
        return True

"And then I recurse into both children. I use or because a match on either side counts as a match overall."

    return self.isSubtree(root.left, subRoot) or self.isSubtree(root.right, subRoot)

想:三段各一句話,邊寫邊防自己的雷。第三段那句 "either side counts" 直接堵住面試官問 "why not and?"。

MOVE 7 · 主動 dry run,用 Move 1 那張圖

"Let me trace my example. Station one, I'm at 3. Comparing 3 against 4 fails on the first value, so I go left. Station two, I'm at 4. Comparing 4, 1, 2 against 4, 1, 2 matches all the way down, so I return true and the whole thing short-circuits. Nodes 5, 1 and 2 are never visited."

想:不要等面試官叫你跑。主動 dry run 是 senior 訊號。

MOVE 8 · 主動掃 edge case,點名誰擋住的

"Three edge cases. An empty big tree hits my first guard and returns false. A single-node subRoot matching a leaf works, because isSameTree treats two nulls as equal. And a partial match, where the big tree has an extra child the small tree doesn't, is caught by the not p or not q line inside isSameTree."

想:「哪個 case 是靠哪一行自動答對的」這種講法,證明你的設計是想出來的,不是試出來的。

MOVE 9 · 主動講 follow-up

"If the interviewer wants better than O(m times n), there's a linear approach. Serialize both trees into strings with explicit null markers, then the subtree question becomes a substring question, which KMP solves in O(m plus n). The null markers matter: without them two different shapes can serialize to the same string."

想:解一類,不是解一題。最後那句 "the null markers matter" 是細節,證明你真的懂,不是聽過名詞。

3(4(1(),2()),5())   ← 括號就是 null marker

只給結論 vs 說明推理

Move只給結論說明推理
0直接開始寫先問「值會不會重複」,把陷阱先擺上檯面
3"I'll check every node.""…if and only if… so I can't miss a match." 把正確性講死
4"I'll use a helper.""I'm trading time for clarity here." 說出成本換了什麼
8"It handles edge cases.""…is caught by the not p or not q line." 點名是哪一行擋的

逐字稿流利、harness 綠、講得出 invariant,這三件事分開看,都不單獨代表職級。職級還取決於目標公司的要求與真實工作影響。

挑進 Native English 的四句

  • "The naive read is to … but that only catches the case where …"
  • "I'm trading time for clarity here."
  • "Each one can trigger a comparison that walks up to n nodes."
  • "Sound reasonable?"
