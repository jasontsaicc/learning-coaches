委派給下屬的樹

Invert Binary Tree。這一題的重點不是翻轉,是遞迴。你在 linked list 用的是 while 迴圈,樹上不能這樣走。

00先學新招:遞迴

遞迴 = 你只做一層的事,剩下的委派給同一個 function 的另一個分身,然後相信它會做對。

你在公司收到一張單子:「把整個 infra/ 目錄底下所有 .tf 檔案格式化」。你有兩種做法。

迴圈的做法:自己維護一個「待辦清單」,把目錄丟進去,一個一個拿出來,是檔案就處理,是目錄就把裡面的東西再丟回清單。清單是你自己宣告的變數,你要自己管它什麼時候空。

遞迴的做法:你看一眼手上這個東西。是檔案 → 處理完收工。是目錄 → 對裡面每一個項目,發同一張單子給下屬,然後等他們回報。你不管下屬怎麼做的。

遞迴永遠只有三個零件

  • 1base case — 什麼時候不再委派,直接回答。少了它 → RecursionError,程式炸掉。
  • 2這一層自己做的事 — 只做一層。不要在腦中往下追。
  • 3委派 — 呼叫自己,但參數是「更小的問題」。

最重要的一句:相信下屬

新手寫遞迴卡住,幾乎都是因為在腦中往下追第二層、第三層,然後腦袋爆掉。不要追。寫 invertTree(root.left) 的時候,直接假設「這行跑完,左子樹已經翻好了」。這叫 recursive leap of faith。

你追不完,而且不需要追。真正需要驗證的只有一件事:如果下屬都做對了,我這一層做的事能不能讓整體正確?能,就對了。這就是 invariant。

每個分身有自己的便條紙

這是你之前踩過的坑的樹上版本(「這行什麼時候被求值」)。每一次呼叫,Python 會給它一組全新的 local 變數,疊在一個叫 call stack 的東西上。

invertTree(root=4)  ← 主管,暫停在「呼叫左邊」那一行,等回報
invertTree(root=7)  ← 下屬,也暫停著
invertTree(root=9)  ← 現在真正在跑的是這一層

三個 frame 裡都有一個叫 root 的變數,它們是三個不同的變數,互不干擾。最底下那層改自己的 root,不會動到上面的。上面兩層就停在那一行,等下面 return。

迴圈 vs 遞迴:同一件事的兩種記帳法

while 迴圈(#206 / #141)遞迴(tree)
誰記住進度你自己宣告的 prev / curr / fastPython 的 call stack
什麼時候停while 條件變 Falsebase case 直接 return
要走兩條路時做不到,只有一個 next呼叫兩次就好
額外空間O(1)O(h)，h = 樹高

樹一定要遞迴的原因就在第三列。Linked list 每個 node 只有一條路,一個 curr 指標走得完。樹每個 node 有兩條路,走了左邊,右邊要留給誰記住?call stack 幫你記。

01這題在幹嘛

把一棵二元樹左右翻過來,像照鏡子。每一個 node 的左右小孩互換,整棵樹都要換。

Input

[4,2,7,1,3,6,9]

Output

[4,7,2,9,6,3,1]

注意葉子 1 3 6 9 變成 9 6 3 1。不是只換根的兩個小孩,是每一層都換。

02什麼型 + 秒認信號

型:Tree DFS(深度優先),遞迴寫法。這是所有樹題的預設起手式,先想 DFS,不行再想 BFS。

  • 1題目給你 root,而且 node 有 .left / .right → 樹題,九成是 DFS。
  • 2「每一個 node 都要做同一件事」→ 遞迴。差別只在做什麼。
  • 3做的事不依賴子樹的回傳值(換小孩就是換小孩)→ 這題特別簡單,是遞迴的入門款。#104 求深度就會依賴回傳值,難一階。

03不用遞迴怎麼做,以及為什麼不划算

可以。你自己維護那張「待辦清單」就好,這就是把 call stack 手動攤開:

手動版:準備一個 stack,先把 root 丟進去。反覆拿一顆出來 → 換它的左右小孩 → 把它的兩個小孩丟進 stack → 直到 stack 空。

複雜度完全一樣:時間 O(n)、空間 O(h)。差別只在誰記帳:手動版你自己開一個 list,遞迴版 Python 幫你開。

所以「遞迴比較快」是錯的

遞迴買到的是可讀性,不是效能。它其實還更慢一點點(function call 有開銷)、也更危險一點(Python 預設遞迴上限約 1000 層,一棵歪掉的樹深度 10 萬就會 RecursionError)。

這跟 #141 那條是同一個教訓:先講清楚換掉了什麼。#141 換的是空間不是時間;這裡換的是可讀性換掉一點效能與堆疊安全。

04做法一步一步(手動走,沒有 code)

用上面那棵 [4,2,7,1,3,6,9]。規則只有一條:站在某一顆 node 上,先把自己的左右手交換,再叫兩個小孩做同樣的事。

step 1 · 站在 4

交換 4 的左右手:左邊原本是 2 那一整包,右邊是 7 那一整包。換完 4 的左邊變成 7 那包。
整包一起搬,不是只搬一顆。

step 2 · 委派給左小孩(現在是 7)

對 7 做同一件事:交換它的 6 和 9。7 底下變成左 9 右 6。

step 3 · 9 和 6 各自也要做

它們沒有小孩,交換兩個 None,什麼都沒發生。這就是 base case 附近。

step 4 · 回到 4,委派給右小孩(現在是 2)

交換 2 的 1 和 3 → 左 3 右 1。它們的小孩也各自跑一次,一樣什麼都沒發生。

step 1 那句「整包一起搬」是這題唯一的關鍵

你交換的是兩個指標,不是兩個數字。root.left 存的是「2 那一整棵子樹的地址」。指標一換,底下掛的東西全部跟著走。這跟 #21 的「尾段可以整段掛」是同一個直覺:動一根指標,搬一整包。

先想清楚:為什麼這樣一定對?

用歸納法,一句話:假設左右子樹都已經被下屬翻好了,那我在這一層把左右指標交換,整棵樹就翻好了。最小的情況(空樹)本來就翻好了。所以每一層都對。

這句話就是你面試時要講出來的 invariant。講得出來,面試官就知道你不是背的。

實際上的樹

2.left 不是「沒東西」,它是 None。所以 invertTree(2.left) 是合法呼叫。

if not root: return None 到底在接什麼

它不是在檢查「我是不是葉子」。它是在接住掉出樹外的那一次呼叫 — 有人把 None 當參數傳進來了。

invert(4)  交換 -> left=7, right=2

格 2. 交換自己的左右手。這一層的工作到此結束,剩下的都是委派。

invert(None)  ∅ 踩空了

格 4. 這就是 base case 那一格。7 把單子發給 7.left,而 7.left 是 None。這一層一進來就撞上 if not root,成立,立刻 return None,不交換、不再委派。

invert(4)  暫停
invert(7)  左邊回來了,換發右邊

格 5. 右邊也是 None,一樣立刻回來。7 的兩張單子都回報了。

invert(7)  return 7

格 6. invert(4) 從格 3 停住的那一行的下一行醒過來。它的 root 還是 4,沒被任何下屬動過。

invert(4)  全部回來了 -> return 4

格 7. 2 那邊跟 7 完全一樣走一遍。收工。

踩空 4 次,不是浪費

那 4 次 invert(None) 就是遞迴的煞車。你不用在每個地方寫 if root.left: 才呼叫 — 讓它踩空,然後在入口統一接住,code 少一半,而且不會漏掉某個分支。

這是遞迴模板最值錢的一個習慣:base case 放在函式最上面,不要放在呼叫端。

溫度計 ②:交換搬到最後,還會對嗎

會。理由只有一句:這一層的交換沒有用到下屬的回傳值。

先交換再委派(pre-order)先委派再交換(post-order)
委派給誰換過之後的 left / right還沒換的 left / right
下屬做什麼把那一整包翻好把那一整包翻好
結果對對

兩包子樹各自都會被翻好,先翻後換、先換後翻,最後長得一樣。順序不影響。

但這是 #226 的特權,下一題就沒了

#104 Max Depth 的這一層要寫 1 + max(left, right) — 它吃下屬的回傳值。那就非得等下屬回來不可,順序不能動。

判準記這一句:這一層用不用下屬的回傳值?用,順序就鎖死;不用,愛擺哪擺哪。

class Solution:
    def invertTree(self, root):
        if not root:                                  # ① base case
            return None

        root.left, root.right = root.right, root.left  # ② 這一層自己做的事

        self.invertTree(root.left)                     # ③ 委派
        self.invertTree(root.right)

        return root                                    # ④ 把自己交回去

root.left, root.right = ...這一層的事交換兩個指標。整包子樹跟著搬

第 ② 行:為什麼不能拆成兩行

你可能會想這樣寫:

# ✗ 錯
root.left = root.right
root.right = root.left   # root.left 已經被上一行改掉了,這裡抄回同一包

結果是左右兩邊都變成原本的右子樹,原本的左子樹整包不見。

這跟你在 #206 踩的雷是同一家的。那題是 nxt = curr.next 不能刪,因為下一行就要把 curr.next 改掉。同一條規則:要覆蓋一個東西之前,先把它存起來。

Python 的 a, b = b, a 之所以安全,是因為 右邊整串先算完(算成一個 tuple),才開始往左邊塞。等於幫你自動存了。

複雜度

  • 時間 O(n) — 每顆 node 剛好被拜訪一次,每次做 O(1) 的交換。
  • 空間 O(h),h 是樹高。這是 call stack 的深度,不是你開的變數。平衡樹 h = O(log n);歪成一條線的樹 h = n,那就是 O(n)。

面試講空間複雜度時,一定要講出「這個空間是 call stack 佔的」。說 O(1) 是最常見的扣分點。

class Solution:
