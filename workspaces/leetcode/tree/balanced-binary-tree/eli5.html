Balanced Binary Tree。外殼跟 #543 直徑一模一樣,只換記帳那一行。

01這題在幹嘛

樹裡的每一個 node,左邊高度和右邊高度最多差 1。全部符合就回傳 True。

先認識「高度」:從這個 node 往下,最深那條腿有幾層。None 的高度是 0。

站在 3 上:左邊 9 高 1,右邊 20 高 2。差 1,OK。其他 node 也都 OK,所以這棵平衡。

02這個「平衡」不是日常用語的平衡

你可能以為比的是題目比的是
左右 node 數量一樣有幾個有多高
葉子都一樣深差 0 層差 ≤ 1 層都可以
看 root 就好一個 node每一個 node

這棵左右 node 數量一樣(各 3 個),root 自己也沒問題。但它不平衡:

陷阱:只檢查 root

root 左右都高 3,差 0。壞掉的是下面兩個 2:一邊高 2、另一邊是空的。所以一定要每個 node 都檢查。這棵在 drill.py 裡標 ★。

03這是什麼型

  • 1要看每一個 node → 樹 DFS,全部走一遍
  • 2每個 node 要先知道左右的高度 → 小孩交上來 → 後序(左 右 中)
  • 3一個 node 要做兩件事:檢查自己、交高度給爸爸 → 雙軌,跟 #543 同款

往上交的永遠是高度

爸爸拿到小孩的數字,要拿來算自己的左右差。所以小孩只能交高度。交差距的話,爸爸算不出自己的差距。

04暴力法:每個 node 都重新量一次高度

最直覺的寫法:站在每個 node 上,呼叫一個 height() 去量左邊、再量右邊。

站在 1 上:量 2 那條腿 → 走過 2、3、4、...
站在 2 上:量 3 那條腿 → 又走過 3、4、...   ← 同一段又走一次
站在 3 上:量 4 那條腿 → 又走過 4、...     ← 又一次

下面的 node 被量了很多次。斜鏈的樹會變成 O(n²)。

浪費的情報:小孩的高度已經算過了。後序走一次,小孩把高度交上來,爸爸直接用,每個 node 只算一次,O(n)。

為什麼紙條一開始寫 True?

檢查那行只會寫 False,沒有任何一行寫 True。一棵平衡的樹,沒有 node 會去碰紙條,紙條停在一開始的值。所以一開始的值 = 沒找到問題時的答案 = True。

完整 code 加逐行解釋先自己寫過再打開 
class Solution:
    def isBalanced(self, root):
        self.ok = True                  # 1 紙條:先假設平衡

        def depth(node):                # 2 內層:交的是「高度」
            if not node:
                return 0                # 3 None 高度 0
            L = depth(node.left)        # 4 左邊交高度上來
            R = depth(node.right)       # 5 右邊交高度上來
            if abs(L - R) > 1:          # 6 記帳:差超過 1
                self.ok = False       #   在紙條寫 False
            return 1 + max(L, R)        # 7 往上交:我的高度

        depth(root)                     # 8 走完整棵樹
        return self.ok                  # 9 交出紙條
行做什麼容易寫錯
1開紙條,放在 self 上初始寫成 False,永遠交 False

4、5遞迴叫 depth叫成 isBalanced(node.left) → NameError
