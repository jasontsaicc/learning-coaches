01這題在幹嘛

現在不是兩列火車，而是 k 列。每列車廂都已由小到大排好；要把所有車廂重新掛成一列，結果仍然由小到大。

03兩個直覺做法，慢在哪裡

A. 全部倒出來再排序

倒出來14513426

把 N 個值放進 array、排序、重建 linked list。時間 O(N log N)，額外空間 O(N)。它浪費了「每條 list 已排序」這份免費情報。

B. 把 #21 從左到右一直做

先 merge list 0 和 list 1，再把長大的結果跟 list 2 merge，繼續直到第 k 條。答案前半段會被重複掃過；最壞可到 O(Nk)。

問題不是 #21 慢，而是合併順序失衡

一條越長越大的結果，每來一條新 list 就重新走一次。後面的 follow-up 會把 lists 兩兩配對，平衡地使用 #21，讓它也能做到 O(N log k)。

04min-heap 做法：一步一步，沒有 code

先只放每條 list 的 head

初始候選人是 1(list 0)、1(list 1)、2(list 2)。heap 最多只有 k 張票，不需要把所有 N 個 node 都塞進去。

概念上的候選集合（只是為了看懂；heap 內部不保證整排排序）
1 · L01 · L12 · L2

整題最重要的 invariant

heap 恰好保存每條尚未合併 list 的當前 head。

每條 list 自己已排序，所以該 list 剩餘最小值一定是它的 head；所有 list 的 head 再取最小，就是所有剩餘 node 的全域最小值。

每一輪固定做四件事

  1. 從 heap pop 最小 head。
  2. 把這個 node 接到 tail 後面。
  3. tail 往前走到新隊尾。
  4. 如果這個 node 原本還有下一個，就把同一條 list 的下一個 node push 進 heap。

為什麼 tuple 要放 list_id？

例子一開始有兩個值都是 1。Python 比 tuple 時會從左往右比：

(node.val, list_id, node)

值相同就比較唯一的 list_id，勝負已分，不會走到第三格去比較 ListNode。如果只放 (node.val, node)，遇到同值時 Python 會嘗試比較兩個 ListNode，產生 TypeError。

複雜度

項目值理由
時間O(k + N log k)先掃 k 條 list；N 個 node 各 pop 一次、最多 push 一次，heap 大小不超過 k
常見簡寫O(N log k)面試時常省略初始化掃描；若 empty lists 很多，精確式更完整
額外空間O(k)heap 最多保存每條 list 的一個 head；答案沿用原 node

完整 code 加逐行解釋預設對照打 
import heapq

class Solution:
    def mergeKLists(self, lists):
        min_heap = []

        for list_id, node in enumerate(lists):
            if node:
                heapq.heappush(min_heap, (node.val, list_id, node))

        dummy = ListNode()
        tail = dummy

        while min_heap:
            _, list_id, node = heapq.heappop(min_heap)

            tail.next = node
            tail = tail.next

            if node.next:
                heapq.heappush(
                    min_heap,
                    (node.next.val, list_id, node.next),
                )

        return dummy.next
變數工作何時改變
min_heap各 list 當前 head 的候選櫃台每輪 pop 一張，可能 push 同來源下一張
list_id同值時的 tie-breaker，也標記 node 來自哪條 list跟著該來源一路傳下去
node這一輪選出的全域最小 node每次 pop 重新賦值
dummy答案固定錨點不動
tail答案目前隊尾每輪前進一次

你最容易犯的兩個錯

  • return dummy.next 必須在 while 外面；放裡面只會回傳第一個 node。
  • node 每輪由 heappop 重新求值。問「第 4 輪的 node 是誰？」要回到當輪 heap，不是沿用第 1 輪的 node。

Follow-up：不用 heap 可以嗎？

可以。把 k 條 lists 兩兩配對，用 #21 merge；下一輪再把結果兩兩配對。每一層所有 N 個 node 只走一次，共 log k 層，所以也是 O(N log k)。

做法時間你怎麼選
Min-heapO(k + N log k)最直接表達「k 個 sorted streams 反覆取最小」；也是本題主講
Divide and conquer + #21O(N log k)最大化重用已會的 #21；適合面試官追問 alternative
從左到右 sequential mergeO(Nk) worst容易想到，但成長中的結果會被反覆掃
