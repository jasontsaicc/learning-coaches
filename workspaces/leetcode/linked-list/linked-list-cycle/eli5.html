Linked List Cycle — 這一招之後在 #142 #143 #876 #287 全部重用

01這題在幹嘛

給你一條鏈的 head。從頭一直走 .next,走得完就回 False,走不完(繞回前面某一顆)就回 True。

沒環1→2→3→4→None

有環的話,鏈的尾巴不是 None,而是指回中間某一顆:

有環 · 3 → 2 → 0 → -4,-4 指回 2

從 3 出發,走進 2 → 0 → -4 → 2 → 0 → -4… 永遠停不下來。那條 3 是進場跑道,後面三顆才是環。

先講一件會害你寫錯的事

環是由 node 物件的身分決定的,不是由 val 決定的。一條鏈裡完全可以有兩顆 val 都是 2 但不是同一顆的 node。所以等一下比較兩根指標時,要用 is,不能用 == 比值。

02這是什麼型

Fast & Slow Pointer(快慢指標),又叫 Floyd's cycle detection。三個秒認信號:

  • S1題目在問鏈的形狀(有沒有環、中點在哪、倒數第 k 個),不是問裡面的值。
  • S2你需要「兩個位置的相對關係」,但不能倒著走。linked list 沒有 .prev,所以只能用第二根指標製造距離差。
  • S3題目或面試官加一句 “can you do it in O(1) space?”。這句話幾乎等於直接點名快慢指標。

秒認公式:形狀問題 + 不准用額外空間 = 放兩根速度不同的指標

跟 #206 反轉那組指標的差別:#206 的 prev / curr 是同速,目的是改鏈。這題的 slow / fast 是異速,目的是不改鏈,只量距離。

03暴力法長怎樣,它輸在哪

最直覺的想法:沿路做記號。準備一個 set,每走到一顆就把它丟進去。

  • 走到 None → 走完了,return False
  • 走到一顆已經在 set 裡的 → 繞回來了,return True

這個做法完全正確,而且時間也是 O(n)。所以它輸的不是速度。

做法時間空間輸在哪
hash set 記走過的 nodeO(n)O(n)鏈有一千萬顆就要存一千萬個參照
快慢指標O(n)O(1)需要想通「為什麼一定會相遇」

這是這題最容易記反的一句

快慢指標不是為了跑得比較快,兩個都是 O(n)。它換掉的是記憶體。面試講「這樣比較快」會被抓,講「same time, constant space instead of linear」才對。

暴力解浪費了什麼免費情報? 它把整條走過的路都背下來,可是判斷有沒有環根本不需要知道路長什麼樣。環是一個「形狀」,不是一組「內容」。你只要有兩個東西在同一條路上用不同速度跑,形狀自己會說話。

04做法,一步一步(沒有 code)

把鏈想成跑道。放兩個跑者在起點:

  • 龜 slow:一次走 1 步
  • 兔 fast:一次走 2 步

然後只看兩件事:誰先撞到路的盡頭,還是兔子從後面追上龜。

發生什麼代表什麼回傳
兔子撞到 None這是一條直路,有盡頭False
兔子跟龜站到同一顆跑道是環形的,兔子把龜套圈了True

用 3 → 2 → 0 → -4(-4 指回 2)手動走一遍

第 3 圈 · 相遇

為什麼「一定」會相遇?(這段是這題的本體)

不要用「跑久了總會遇到」這種說法,那在面試會被追問。正確的講法是看距離怎麼變:

兩人都進環之後,兔子每一圈就把差距剛好縮短 1

兔子一圈走 2 步,龜一圈走 1 步,所以每一圈兔子淨賺 1 步。設「兔子還差幾步追到龜」是 d:

d 是一個非負整數,而且每圈剛好減 1。一個每次只減 1 的數字,不可能跳過 0。所以它一定會踩到 0,也就是一定會有某一圈兩個站在同一顆。

「不可能跳過 0」是整個證明的關鍵字。如果兔子一次走 3 步,差距每圈減 2,就有可能從 1 直接跳到 -1,永遠錯過。 這就是為什麼是 2 步,不是 3 步。

沒環的那半邊怎麼保證會停?

沒環的鏈長度有限,而兔子每圈前進 2,所以它先撞到 None。撞到就跳出迴圈回 False。所以兩種情況都會結束,不會無限迴圈。

接下來的區塊,你自己決定何時打開

先把上面第 4 節「為什麼一定會相遇」用自己的話講一遍,再展開 code。

完整 code 加逐行解釋先自己講一遍再開 
def hasCycle(head):
    slow = head
    fast = head

    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True

    return False
行它在幹嘛為什麼一定要這樣寫
slow = head
fast = head		兩個跑者都站在起跑線差距從 0 開始。所以不能在走之前就檢查相遇
while fast and fast.next確認兔子還有 2 步可以走下一行要讀 fast.next.next,需要 fast 活著而且 fast.next 也活著

為什麼 while fast and fast.next 的順序不能反

Python 的 and 是短路求值:左邊是 False 就不看右邊了。

  • fast and fast.next → fast 是 None 時直接停,不會去讀 None.next
  • fast.next and fast → fast 是 None 時先讀 None.next → AttributeError

這跟你在 stack 題犯過的「not stack 要放 or 左邊保護 stack[-1]」是同一條規則:把守門的條件放在會爆炸的條件前面。

你最可能犯的錯從你自己的紀錄撈的

1. return False 縮排卡進 while 裡(你犯過 4 次,清單第 1 名)

症狀:不報錯,但是每一條鏈都回 False,因為第一圈跑完就 return 掉了。這種錯最貴,因為它安靜。

2. 迴圈條件只寫 while fast:

症狀:AttributeError: 'NoneType' object has no attribute 'next'。看到這行錯誤,第一個懷疑就是少檢查了一格。記法:你要跳幾格,就要檢查幾格。

3. 用 == 比兩根指標

slow.val == fast.val 或 slow == fast 比的是值。值可以重複,會誤判成有環。比 node 一律用 is。

✗ if slow.val == fast.val:
✓ if slow is fast:
→ 你今天問的「head 跟 curr 是等於還是指向」就是這件事:標籤貼在物件上,is 問的是「兩張標籤貼在同一顆嗎」

4. 在移動之前就檢查相遇

兩根都從 head 起,所以還沒走的時候 slow is fast 本來就是 True。檢查寫在迴圈開頭 → 任何鏈都回 True。先走,再比。

def hasCycle(head):
