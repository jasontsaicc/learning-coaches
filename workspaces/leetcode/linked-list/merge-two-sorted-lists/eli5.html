合併兩條有序火車

Merge Two Sorted Lists — 也是 #23 Merge K Sorted Lists 的地基

01這題在幹嘛

兩列車廂編號都已經由小到大排好了。把它們合成一列,合完還是由小到大。

關鍵字是 「已經排好」。你不是在排序,你是在拉拉鍊:兩邊各站一個人,每次看誰的車廂編號小,就把那一節先掛上去。

list11→2→4→∅
list21→3→4→∅
答案1→1→2→3→4→4→∅

顏色是為了讓你看出哪一節來自哪一列。沒有新造任何車廂,只是把原本的車廂重新掛鉤。這件事等一下會變成複雜度的重點。

02這是什麼題型

Two Pointers 走在 linked list 上的「合併」型。三個秒認信號:

  • S1輸入已經排序。題目送你一份免費情報,你的解法必須用到它,否則就是浪費。
  • S2輸出也要求排序,而且要求的是同一種順序。
  • S3題目動詞是 merge / 合併 / 交錯,不是 search、不是 count。

三個一起出現 = 雙指針各站一邊,每輪挑小的接走

這時候你不需要任何排序演算法。看到 S1 就想「我可以只掃一遍」。這個直覺之後在 merge sort、merge K lists、合併區間都會重複用到。

03暴力法長怎樣,為什麼慢

最直覺的做法:兩條全部倒進一個 array,呼叫 sort(),再重建一條 linked list。

倒出來124134
sort112344
重建新→新→新→… 六節全新的車廂

它會過,但兩邊都輸

  • 時間 O((n+m) log(n+m)) — sort 的錢。而題目已經幫你排好了,你等於付錢買一份免費的東西。
  • 空間 O(n+m) — array 加上全新的 node。

面試官問「已經排序這個條件你用在哪裡?」的時候,暴力法答不出來。這就是它被扣分的地方,不是它跑得慢。

04做法,一步一步(沒有 code)

用上面同一組資料手動走一遍:list1 = 1→2→4,list2 = 1→3→4。

先講一個小道具:dummy 假車頭

我們造一節空車頭掛在最前面,它不存資料,只是給人站。再派一個叫 tail 的人,永遠站在「目前已經接好那串的最後一節」。

起手dummy→∅　　← tail 站在 dummy

為什麼要 dummy?

沒有它的話,「掛第一節」要寫特例判斷(答案的頭還不存在),「掛第二節之後」才是正常流程。有了 dummy,掛第一節和掛第 n 節變成完全一樣的動作。這是 linked list 的通用招:dummy head 消除頭部特例,不只這題用。

然後每一輪做同一件事

  1. 看兩邊的當前車廂,誰的編號小。
  2. 把小的那一節掛到 tail 後面。
  3. 被拿走的那一列往前走一節。
  4. tail 也往前走一節,重新站到隊尾。
輪 1d→1　1 vs 1,平手取 list1 ｜ tail 移到這節
輪 2d→1→1　2 vs 1,取 list2
輪 3d→1→1→2　2 vs 3,取 list1
輪 4d→1→1→2→3　4 vs 3,取 list2
輪 5d→1→1→2→3→4　4 vs 4,平手取 list1

收尾:有一列空了

輪 5 之後 list1 走完了,list2 還剩 4。不用一節一節接。

收尾d→1→1→2→3→4→4→∅

因為 list2 自己是排好序的,而且它剩下的每一節都不小於剛剛接走的那節。所以整段直接掛上去就對了。一個動作,不是一個迴圈。

最後回傳誰?

回傳 dummy.next,不是 dummy。dummy 是鷹架,拆掉才交屋。

複雜度

項目值為什麼
時間O(n + m)每節車廂只被看一次、掛一次
空間O(1)沒造新 node,只改掛鉤。dummy 是唯一那一節,常數

完整 code 加逐行解釋先自己講一遍再開 
def mergeTwoLists(self, list1, list2):
    dummy = ListNode()          # 假車頭,val 是什麼都不重要
    tail  = dummy               # tail 永遠站在「已接好那串」的最後一節

    while list1 and list2:      # 兩邊都還有貨,才需要比較
        if list1.val <= list2.val:
            tail.next = list1   # 改掛鉤:把 list1 這節掛到隊尾
            list1 = list1.next  # 移動標籤:list1 往前走一節
        else:
            tail.next = list2
            list2 = list2.next
        tail = tail.next        # tail 跟上,重新站到隊尾

    tail.next = list1 or list2  # 剩下的整段掛上。一定有一邊是 None
    return dummy.next          # 拆鷹架。注意這行在 while 外面

四個變數各自在做什麼

變數它是誰什麼時候變
dummy假車頭,答案的錨點從頭到尾不動,所以最後找得回答案的頭
tail目前隊尾那一節每圈往後一節
list1第一列還沒被拿走的頭只有它被選中那圈才動
list2第二列還沒被拿走的頭只有它被選中那圈才動

三個容易滑過去的地方

  • tail.next = list1 和 list1 = list1.next 長得像,做的事相反。左邊有 .next 是改掛鉤,右邊有 .next 是我往前走。
  • list1 or list2 是 Python 的短路:回傳第一個不是 None 的那個。跳出 while 時至少有一邊是 None,所以這行等於「把還活著的那段掛上」。兩邊都 None 也對,掛上 None 就是結尾。
  • <= 而不是 <:平手時取 list1。功能上兩者都會過,但 <= 保住 stable 的順序,而且 merge sort 靠這個性質。

這次的釐清session 結束時補寫

2026-08-30 第一場。這三個都來自 Layer 0,不是這題本身,但它們是這題會踩雷的根。

✗ 我以為:print(n) 和 return n 差不多,都是「把 n 交出來」
✓ 其實是:print 印到螢幕,函式繼續跑,想印幾次就幾次。return 把值交回呼叫者,而且函式當場結束,只能發生一次。
→ 為什麼會搞混:兩個都「輸出一個東西」,看起來同類。但一個是副作用,一個是控制流。用 shell 對照最快:echo 之於 exit。
✗ 我以為:for n in [7,8,9]: print(n); return n 會回傳 7、8、9 三個
✓ 其實是:只回傳 7。return 在迴圈裡面,第 1 圈就結束整個函式,8 和 9 從沒被碰過,連 print 都只印一次。
→ 為什麼會搞混:縮排看成排版,不是看成「這行歸誰管」。判準:問自己「這個動作該做幾次?」每圈一次就在迴圈內,跑完做一次就在迴圈外。這是你犯過 4 次的最貴錯誤,而且它不報錯。
✗ 我以為:迴圈跑完之後 n 就不存在了,沒東西可以回傳
✓ 其實是:Python 裡 n 還活著,值停在最後一圈的 9。只有 def / class / lambda / comprehension 會建立新 scope,for / while / if / try 都不會。
→ 為什麼會搞混:腦裡裝的是 C 家族的規則(for (int n : nums) 出了大括號就死)。陷阱:如果 list 是空的,迴圈一圈都沒跑,n 從沒被賦值 → NameError,不是回傳 None,是直接炸掉。

這三個怎麼咬到 #21:第 2 條就是 return dummy.next 必須在 while 外面的理由,也是 tail = tail.next 必須在 if/else 外面的理由。同一個心智模型,兩個不同的行。
