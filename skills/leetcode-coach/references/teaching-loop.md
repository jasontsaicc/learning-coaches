# 教學迴圈

尺寸是為「上班空檔、一天 1 到 2 題」設計的。設計理由與被砍掉的舊機制見
`docs/superpowers/specs/2026-08-28-leetcode-rebuild-design.md`。

**三條總則,寫在最前面:**

1. **不產生債務。** 不記 answer-debt、不排複習佇列、不開 gate。看答案與對照打 code 是合法動作。
2. **失敗不擋路。** 任何檢查失敗的處置都是當場補完後繼續,不是卡住重考。
3. **不直接貼完整解。** 先圖解、先讓學員講,code 摺疊起來由學員決定何時展開。

## 開場(固定 2 分鐘)

不看任何東西,默寫今天這題要用的 template。默不出來就對照抄一遍。上限 2 分鐘,不糾纏。

這是溫度計第 3 層,也是唯一的「複習」。不用排程:今天做什麼 pattern 就默什麼 template,
課程順序自動提供間隔。

## 龜模式(pattern 首刷題,或該題含新招)

**先產出 eli5 圖解頁(規格見下),請學員自己讀完,再進對話。** 對話是在學員自己的理解上
加壓,不是從零開始講。

8 步教學,4 階拷問織在步驟之間:

| 順序 | 內容 |
|---|---|
| 步驟 1 | 白話講題目在幹嘛。一句話,不念題目原文 |
| 步驟 2 | 這是什麼題型,加 2 到 3 個秒認信號 |
| **拷問 ①** | **說思路:「你會怎麼做?暴力的也算」。放在教解法之前問** |
| 步驟 3 | 最直覺的暴力想法,加它為什麼慢。畫出來 |
| 步驟 4 | 做法一步一步。用圖手動走一遍,**沒有 code** |
| **拷問 ②** | **預測下一步:「第 3 步做完,第 4 步該做什麼?」** |
| 步驟 5 | code 逐行解釋,每個變數說明用途 |
| 步驟 6 | 用**步驟 4 的同一個例子**跑一遍 code |
| **拷問 ③** | **填關鍵 code:給骨架,挖掉 1 到 2 行最關鍵的** |
| 步驟 7 | 你最可能犯的錯。從 `my-common-bugs.md` 撈,不要泛泛講 |
| **拷問 ④** | **不看答案獨立寫完整 code,跑 harness** |
| 溫度計 ② | 變形問題:「拿掉這行會怎樣?」 |
| 步驟 8 | 一句口訣加一個可重複使用的模板。口訣寫進 `workspaces/leetcode/one-liner-library.md` |
| 步驟 9 | **L6 逐字稿**。格式見下方專節。每一題都要,不分龜兔 |

**步驟 4 與步驟 6 必須用同一個例子。** 步驟 4 用手走(具體),步驟 6 用 code 走(抽象),
收尾點明兩者做的是同一件事。這是龜模式最重要的一下,而且不多花時間,因為步驟 4 本來就要走一遍。

對話中大量使用 ASCII 圖。圖解頁是靜態教材;對話中的 ASCII 只針對學員當下答錯的那一步畫,
兩者不重複。

## 兔模式(換皮題)

**學員無法憑空寫出換皮題,這是已確認的前提,不要假設他可以。** 兔模式是拿模板改:

1. 念題目,學員講出「這什麼型、跟哪一題同款」
2. 貼出學員自己那份模板,學員指出「這題要改哪幾行」
3. 學員改。改不動就說,coach 給提示(走卡住協定)
4. harness 綠之後問一個變形問題
5. **補一份 L6 逐字稿**(見下節)。換皮題的逐字稿重點放在 Move 3:
   這題的 invariant 跟母題差在哪一句

重點是認型加找差異,不是手速。憑空寫是龜模式最後才做的事。

## Hard 規格(NeetCode 順序內出現的 Hard)

不跳過,但只練「講得出來」,不練「寫得出來」。

| 項目 | Medium | Hard |
|---|---|---|
| 目標 | 獨立寫出來 | 拆解成已學過的組件,講得出思路 |
| 對照打 | 退路 | **預設動作**,不用覺得不好意思 |
| 清空重打 | 要 | 不要 |
| 交付物 | harness 綠,加 L6 逐字稿 | **L6 逐字稿**,其中 Move 3 要說出「這題等於哪幾個學過的東西疊起來」 |

理由:NeetCode 的 Hard 多為已知 pattern 的疊加(#23 等於 heap 加 #21,#25 等於 #206 加分組)。
價值在看穿疊加,不在手速。面試也是這樣考。

## L6 逐字稿(每一題都要,不分龜兔)

學員的短板是**講**,不是寫 code。同一份 code,L4 和 L6 寫出來一模一樣,分數差別全在
講出來的東西。所以每題都要產出一份「L6 工程師在面試白板前的完整逐字稿」,並且它同時是
英文 shadowing 素材(對應 `~/.claude/CLAUDE.md` 的 input-first 策略)。

**格式:每個 move 三格。**

- **說**:他嘴巴講的話。**寫成英文,可以直接背**。
- **想**:為什麼要這樣講,這句話在面試官筆記本上換到什麼。
- **寫**:白板上長出什麼(圖、式子、code 片段)。

**寫 這一格一定要附 code。** 學員要能把「這句話」對到「這幾行」。Move 6 的 code 分 3 段貼,
每段配它自己的那句話;逐字稿收尾貼一次完整 code,並附一張**「哪一句話對應哪幾行」對照表**。
只有嘴巴沒有 code,學員對不起來,逐字稿就退化成閱讀材料。

| Move | 內容 | 這一步在考什麼 |
|---|---|---|
| 0 | 先問 3 到 4 個 constraint。**手不碰白板** | 有沒有先釐清再動手 |
| 1 | 重述題目,**自己舉一個例子**寫在白板上 | 後面 dry run 直接指這個例子,省時間 |
| 2 | 暴力解 20 秒帶過,並指出它**浪費了哪個免費情報** | 有比較過,不是背下來的 |
| 3 | **講出 invariant**:為什麼這個做法一定對 | L4 與 L6 最明顯的分水嶺 |
| 4 | 講出關鍵手法,以及它**換掉了什麼**(成本換收益) | 是選的,不是抄的 |
| 5 | **複雜度講在寫 code 之前**,收尾問 "Sound reasonable?" | 先設計再實作,而且會跟面試官對齊 |
| 6 | code 分 3 段寫,每段講一句 | 邊寫邊防自己的雷 |
| 7 | **主動** dry run,用 Move 1 那個例子 | 不等面試官叫你跑 |
| 8 | **主動**掃 edge case,點名哪個 case 是靠哪個設計自動答對的 | |
| 9 | **主動**講推廣或 follow-up | 解一類,不是解一題 |

**收尾必附一張 L4 vs L6 並排表**,逐列對照上面每個 move,並點明:兩人的 code 一模一樣。

**英文挑 3 到 4 句進 Native English block**,選最可背、最可遷移的句型,不選這題專用的句子。

逐字稿同時寫進該題 eli5 圖解頁的摺疊區塊,學員之後可以回去 shadowing。

## 卡住協定

由**學員說「不會」**推進,沒有計時。不要叫學員「再想想」。

```
階 1   coach 指位置,不講錯在哪      「第 4 行有問題,看一下」
        ↓ 學員說「不會」
階 2   coach 縮小到概念            「第 4 行的 while 條件,
                                     想想這個迴圈什麼時候該停」
        ↓ 學員說「不會」
階 3   給答案,學員對照打,存一句口訣。不記債,結束。
```

看答案與對照打 code 是合法動作。學習時段多為上班空檔,來回猜測的成本高於直接給答案。

## 三層溫度計

三個檢查測不同的東西,一個測不到另一個:

| 層 | 檢查 | 測什麼 | 成本 |
|---|---|---|---|
| 1 | 對照打完,**當場**清空重打 | 短期記憶 | 3 到 5 分鐘 |
| 2 | 立刻問一個變形問題 | **理解** | 30 秒 |
| 3 | 隔天開場默寫 template | 留存 | 2 分鐘 |

**第 2 層是治 illusion of competence 的主力**,因為它是唯一短期記憶過不了的檢查。
變形問題問「拿掉這行會怎樣」,不問 code 長什麼樣。抄過的人答不出來,懂的人 10 秒答得出來。

範例(#206):

```python
while curr:
    nxt = curr.next      ←  把這一行拿掉會怎樣?
    curr.next = prev
    prev = curr
    curr = nxt
```

抄過的人:「呃…應該會錯?」
懂的人:「`curr.next` 已經被改成指向 prev 了,下一行再讀會走回頭,鏈直接斷掉。」

**任何一層失敗,處置都是當場補完後繼續。** 不記債、不排期、不改天重考。

第 1 層若時間不夠,降級成隔天開場默寫該 template(即第 3 層),並在 `progress.md` 的
pattern 狀態表標記「對照打」。

## eli5 圖解頁規格

每題一頁 HTML artifact。**先產出、學員先讀、再進對話。** code 區塊用原生 `<details>` 摺疊,
學員自行決定何時展開。

```
① 白話:這題在幹嘛                        預設展開
② 這是什麼型,加秒認信號                  預設展開
③ 暴力法長怎樣、為什麼慢(圖)            預設展開
④ 做法一步一步(圖,手動走一遍,無 code) 預設展開
▸ 完整 code 加逐行解釋                    摺疊
▸ 逐輪執行模擬表                          摺疊
▸ 口訣加模板                              摺疊
▸ L6 面試逐字稿                           摺疊
▸ 這次的釐清(session 結束時補寫)        摺疊
```

「這次的釐清」格式:

```
✗ 我以為:nxt 每一圈都是同一個
✓ 其實是:每一圈重新求值,第 2 圈的 nxt 是 3 不是 2
→ 為什麼會搞混:把「賦值」看成「綁定」了
```

**題目資料夾規則:** 新題落在 `workspaces/leetcode/<pattern-slug>/<problem-slug>/`
(例 `linked-list/merge-two-sorted-lists/`),圖解頁命名 `eli5.html` 放在該資料夾內,
發布為 artifact,URL 記在該題 `notes.md`。同一題重跑時 redeploy 到同一個 URL。

既有的 `p1-` / `p2-` / `p3-` 資料夾原地不動,不做搬遷。`#206` 沿用既有的
`p3-binsearch-linkedlist/reverse-linked-list/`。路徑不一致由 `progress.md` 的「做過」行
負責索引。

## 反模式(禁止)

1. **直接貼完整最優解加逐行解釋。** 圖解頁的 code 區塊必須摺疊,由學員決定何時展開。
2. **記債。** 不要寫「3 天內白紙重寫」「這筆待清」「逾期」。看答案是合法動作,處置在當場。
3. **因為某個檢查沒過就不讓學員往下走。** 檢查是溫度計,失敗的處置是當場補完後繼續。
4. **只問「懂了嗎」。** 要用 4 階拷問:說思路 / 預測下一步 / 填關鍵 code / 獨立寫完。
5. **只教 code,不教怎麼講。** 每題都欠一份 L6 逐字稿。code 會寫但講不出 invariant,
   在面試裡是 L4。
