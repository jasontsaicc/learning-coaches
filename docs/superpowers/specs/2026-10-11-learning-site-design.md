# 個人學習網站第一版改版設計

日期：2026-10-11。狀態：使用者已確認「逐章、多題型、驗證理解」修訂方向，進入實作計畫。

## 目的與範圍

把既有 Learning Map 改成每天能快速接續閱讀、找到教材與逐章檢驗理解的個人入口。
使用者要求更好維護、更好的視覺效果及新增功能規劃，並確認保留靜態網站、拆分原生 JS
模組、實作第一版 P0 功能的方向。以個人使用為本輪前提；多人服務與公開作品集另行規劃。

使用者追加要求：練習依章節組織，包含選擇、填空、排序等多種互動，檢驗理解與應用，
不能只有名詞 flashcards。章節練習提升為第一版核心；跨課程混合卡片不再是主要練習入口。

成功條件：首頁直接提供可用的下一步；手機閱讀順暢；搜尋能找到已匯出的主題與筆記；
每個章節有清楚的練習入口及題庫狀態，題目能測到機制、預測與判斷；
複習紀錄沿用；正式能力評量不因瀏覽、自評或選擇題分數而提升。

## 現況與選擇

- `site/build.py` 使用 Python 標準函式庫，把允許的課綱、進度與筆記轉成 `data.json`。
- `site/index.html` 集中 CSS、路由、D3 地圖、Markdown 閱讀與 Leitner 複習。
- 現有 `#/`、`#/c/<coach>` 連結以及筆記檔案路徑需要保留。
- 卡片紀錄在瀏覽器 `localStorage` 的 `srs`，不回寫教練資料。

只改 CSS 無法解決功能耦合；改用框架與後端會增加目前不需要的建置及資料服務。
本版沿用靜態生成、原生 ES modules、現有插圖與套件，按實際責任拆分。

## 頁面與使用流程

### 首頁

順序為頁首／搜尋、繼續閱讀與今日複習、課程卡。
繼續閱讀顯示最近在網站內開啟的主題或 Markdown 筆記與所屬課程；首次使用顯示選課入口。
瀏覽位置不是正式課程斷點，不推測下一個教練任務。
首頁提供「繼續章節練習」與按章節列出的待重練項目，進入後只練該章。
既有 flashcards 保留為輔助記憶入口，與章節練習分開，不以到期卡數代表學習任務總量。
課程卡使用真實資料呈現階段與學習狀態，不把全部未開課内容當作未完成作業。

### 課程與筆記

縮小課程封面，優先呈現課程名稱、進行中階段與操作。
階段可收合；初次進入展開進行中階段，無進行中標記時展開第一個階段。
手機採垂直節點排列，標題自然換行；桌面保留現有路徑特色。
重點、筆記與知識地圖入口清楚分組，地圖按需繪製。

Markdown 改為站內閱讀頁，提供返回課程、標題目錄與閱讀位置恢復。
閱讀路由以編碼後的已匯出檔案路徑定位，開啟前核對 `data.json` 的檔案清單。
既有 HTML 筆記繼續以新頁開啟；本版只記錄開啟紀錄，不追蹤其內部捲動位置。
Markdown 延續 DOMPurify 清理；網站內的普通文字持續跳脫。
閱讀位置只存於本機，失效的檔案引用顯示提示並提供返回入口。

### 搜尋

搜尋範圍為已匯出的主題名稱、筆記標題及檔名，不新增全文索引。
採前端字串比對，忽略英文字母大小寫與輸入前後空白。
結果附課程與類型，相同筆記路徑去重；選取後打開相應主題或筆記。
空輸入顯示操作提示，零結果顯示清除搜尋入口。使用標準表單與連結／按鈕支援鍵盤。

### 章節練習：主要學習檢查

資訊層級為課程 → Phase／主題群 → 章節 → 練習題。
章節指可獨立學習的一個單元，例如 K8s 的 Service 或 Readiness、SD 的 Cache-Aside，
而不是把整個網路 Phase 當成一章。LeetCode 以一題或一個明確概念單元為章節。
章節對現有主題的對照由題庫明列，不依 topic 陣列位置產生 ID，也不改動教練課綱。
題庫中一個章節可對照同一概念的多筆既有主題；未建立對照的主題顯示「練習尚未建立」。

每章呈現學習目標、教材入口、練習題數及練習結果。流程是：
選章 → 看本輪目標 → 逐題作答 → 看原因與教材連結 → 章節結果 → 重練弱項。
一輪預設 5–8 題，題庫不足則顯示實際題數，不重複湊數。至少涵蓋兩個目標及三種互動，
包含一題條件改變後的預測或情境判斷。未達覆蓋標準可供試練，但不得標成完整章節檢查。

第一版支援以下互動：

| 題型 | 檢查目標 | 判分方式 |
|---|---|---|
| 單選／多選 | 因果、故障原因、方案取捨 | 比對選項 ID；多選需集合完全相同，逐項回饋 |
| 填空 | 關鍵機制、程式／設定缺口、計算 | 題目明列可接受答案；只做指定正規化，數值可明列單位與容差 |
| 排序 | 資料流、執行順序、依賴關係 | 比對穩定步驟 ID；若有多種合理順序需明列，否則改寫題目 |
| 配對／分類 | 分清角色、層次與概念邊界 | 比對各項對應目標；逐項解釋混淆點 |

情境、程式碼／YAML／log 閱讀、結果預測是題目內容，可搭配上述互動，不各寫一套 renderer。
排序同時有上下移動按鈕；配對可用點選或選單完成，拖曳只是可選互動，不能成為唯一操作。
程式、設定與 log 都作為文字材料顯示，不在瀏覽器或伺服器執行使用者答案。

每題作答前可選「確定／不確定」，不影響分數；提交後顯示正解、機制說明、
錯誤選項或常見誤答的原因、對應教材。提示與解答在提交前預設收合。
看過提示的答對標成「提示後答對」；揭示答案後重試標成「練習後答對」。
結果分開顯示首次無提示答對、提示後答對、仍待練習與略過，不用最終全對掩蓋首次錯誤。
對不確定、答錯或用過提示的目標提供同概念變式；缺少變式時明示為原題重做，不能當成遷移證據。
本版重練由使用者啟動，不新增自動間隔排程或虛構到期時間。

### 題目內容與「真的學會」

題型多樣只是互動手段；題目需對應明確學習目標及常見誤解。
每章由辨認機制進到預測流程，再到條件改變後的情境應用，避免只有定義填空。
選項不能靠長度、語氣或固定位置提示答案；干擾選項應代表可解釋的錯誤心智模型。
變式要改變條件與推理要求，不能僅換名詞或洗牌選項。

章節結果顯示「哪些目標有作答證據、哪些仍需重練」，不宣稱等同實作熟練或 Phase Gate 通過。
需要自行解釋或實際操作的能力，提供章末挑戰與檢查標準，標示「待教練／實作驗證」。
本版不以關鍵字比對替開放回答評分，也不新增 AI 自動判分服務。

### 題庫與作答紀錄

題庫使用 `site/exercises/<coach>.json`，由版本控制管理；內容基於現有可公開教材整理，
每題附來源相對路徑及段落，不從私人的 session logs 自動產題。
先以 K8s、SD、LeetCode、CA 各一個有現成教材的章節驗證題型、語意和流程，
其餘章節按相同品質標準補齊；介面全面支援逐章，但首批不能宣稱全課程題庫完成。
首批章名為 K8s 探針、SD Cache-Aside、LeetCode Linked List Cycle、CA VPC Peering。
前三者沿用既有筆記並校對；CA 補一份經官方文件核對的 `portfolio/ca/notes/vpc-peering.md`，
由既有 portfolio notes 匯出規則讀取，不匯出教練內部文件。

章節欄位：穩定 `id`、`coachId`、`phaseId`、`title`、`topicRefs`、`objectives`、`sources`、`questions`。
题目共用欄位：穩定 `id`、`revision`、`type`、`objectiveId`、`prompt`、`hint`、`explanation`、
`source`、可選 `variantOf`；選項、答案及錯誤回饋依題型保存，避免包成任意可執行條件。
建置驗證 ID 唯一、章節／目標引用有效、來源在允許集合、答案與選項一致、排序項目完整、
填空規則明確及必要解說齊全。缺題型或題庫為空應顯示狀態，不讓頁面靜默消失。
答案在靜態資產中可見，定位是自學檢查，不作防作弊測驗。

作答保存在獨立且帶版本的 localStorage key，記錄章節／題目 ID、題目 revision、作答、
是否提示、信心與首次結果，支援中途離開後接續。舊 `srs` 完全獨立保留。
題目答案或語意改動需增加 revision；舊紀錄可保留但不能當成新版已通過。
損壞資料或儲存失敗需提示，不默默清空；只記錄答題必要資訊，不收集自由輸入的私人筆記。

### Flashcards：輔助記憶

共用現有卡片來源與 Leitner 間隔，不引入另一套評分或排程演算法。
每次從所選課程的到期卡選取最多 20 張不同卡片；跨課程混合模式延後。
答錯卡可在本輪重試一次，之後留待後續複習，避免反覆答錯造成無限迴圈。
完成畫面明確寫「本輪完成」並顯示剩餘到期卡，不把一輪 20 張當成全部完成。

沿用舊卡片 ID、`srs` key 與 `{box, due}` 格式；不因拆分程式重置紀錄。
驗證讀取的容器、盒數與到期值，異常紀錄需提示，不能悄悄覆寫整份原始資料。
儲存失败時明確表示本次紀錄未保存，並保留當前畫面與記憶體內進度。
本版保留既有以 UTC 日序計算到期的方式，介面註明複習日以 UTC 更新；時區遷移另議。

## 進度語意與資料界線

- 教練評量保留原始等級，不能把 `med-high` 的配色簡化當成確切 `high`。
- LeetCode「做過」只產生已練習狀態，不自動產生 `high`；沒有評量就顯示未評量。
- 瀏覽紀錄、章節作答、卡片自評與正式教練進度分開呈現；前三者均不覆寫後者。
- `workspaces/`、歷史目錄及課程內容不因本次開發而變動。
- 教材匯出白名單維持原範圍；新增經驗證的 exercises 題庫，不新增 session logs、職涯資料或課程斷點。
- Terraform 未有現成網站資料時不建立空課程或虛構進度。

目前 topic ID 含陣列位置，可能隨資料增減改變。最近閱讀的主題使用課程、父階段及完整標題
核對；匹配不唯一或已移除就顯示無法恢復，不錯開另一個主題。
本版不提供可對外長期引用的主題固定連結；筆記閱讀路由則沿用檔案路徑。

## 視覺與無障礙

保留奶油色背景、四門課程的粉彩插圖與主要按鈕的輕微立體效果。
共用 CSS 變數統一顏色、間距、字級、圓角與陰影；一般資訊卡減少裝飾陰影。
主操作突出，次操作降低視覺重量；中文閱讀行距約 1.7，正文採舒適的有限寬度。
學習狀態同時使用文字與圖示，不能僅靠顏色；可點擊區域至少 44px。
具備可見焦點、語意化控制項、彈窗焦點管理與關閉後焦點恢復。
遵守 reduced-motion，手機 360px 寬度沒有頁面水平溢出；程式碼及表格可在區塊內捲動。

## 檔案責任與影響範圍

| 檔案 | 責任／調整 |
|---|---|
| `site/index.html` | HTML 骨架、套件載入、module 入口 |
| `site/styles.css` | 視覺規則與響應式樣式 |
| `site/app.js` | 資料索引、路由、搜尋、閱讀位置與頁面渲染 |
| `site/review.js` | 複習排程、佇列、儲存與複習介面 |
| `site/exercises.js` | 共用作答流程、各題型渲染、判分及紀錄；不為每章複製頁面 |
| `site/exercises/<coach>.json` | 章節、目標、題目與解說；新增同題型章節只改資料 |
| `site/map.js` | D3 地圖與選取互動 |
| `site/build.py` | 修正 LeetCode 狀態輸出，驗證並匯出題庫，複製新增靜態資產 |
| `site/test_build.py` | 狀態輸出與資產契約的必要回歸檢查 |
| `site/test_review.mjs` | 以 Node 內建測試覆蓋排程、重試及舊紀錄相容性 |
| `site/test_exercises.mjs` | 各題型判分、提示／首次結果、題目改版與續答的回歸檢查 |
| `scripts/lint-all.sh` | 串接新增的必要自動檢查，明確檢查 Node 可用性 |
| `site/README.md` | 更新模組與使用說明，保留現有使用者改動 |

模組透過函式參數接收需要的資料與 callback，避免循環 import 或新增全域狀態容器。
不新增 npm 依賴或前端 bundler；現有套件載入與 SRI 維持。

## 失敗與空狀態

資料與筆記 fetch 檢查 HTTP 狀態並處理失敗，畫面提供重試或返回。
快速切換筆記時，過期請求不得覆蓋後開啟的筆記。
錯誤路由、缺少筆記、無搜尋結果、無到期卡分別呈現清楚訊息。
D3 不可用時仍能使用課程與筆記；Markdown 解析器不可用時提供純文字備援。
localStorage 不可用時仍可瀏覽，依操作提示閱讀位置或複習紀錄無法保存。

## 驗收

1. 原有首頁、四門課程、筆記與地圖仍可開啟，重新整理課程／閱讀連結不會空白。
2. 新增靜態檔案會被建置複製，輸出的頁面可以直接由既有靜態伺服器服務。
3. 桌面與 360px 手機寬度截圖檢查首頁、長標題課程、閱讀頁、複習及空狀態。
4. 鍵盤可搜尋、展開階段、閱讀、翻卡、評分及關閉彈窗；焦點不落到背景。
5. 舊 srs 紀錄可載入；答錯重試有上限；到期量超過 20 時完成提示不誤導。
6. HTTP 失敗、過期筆記請求、損壞／無法寫入的儲存均有對應處理與針對性檢查。
7. LeetCode 做過的題目不再被自動標為 high；教練原始等級正確顯示。
8. 既有 parser 檢查、新增必要測試及 `./scripts/lint-all.sh` 通過。
9. git diff 確認沒有 workspaces 或歷史資料變更，未覆蓋使用者既有修改。
10. 每章顯示練習入口或尚無題庫狀態；一輪不會混入其他章節題目，首批覆蓋範圍明示。
11. 單選、多選、填空、排序、配對／分類均可使用滑鼠、觸控及鍵盤完成；反例判分有測試。
12. 錯題回饋能指出具體誤解並連回教材；至少一個示範章節完整呈現機制、流程與應用層次。
13. 首次無提示結果不被重做覆寫；提示、未答、變式不足及題目改版不誤標成已掌握。
14. 非法題庫在建置時失敗並指出章節／題目；舊 srs 仍可用，章節續答有獨立儲存檢查。

## 後續功能

P1：擴充所有章節題庫與變式、收藏、穩定主題連結、練習／複習紀錄匯出／匯入、
附評量來源的待加強主題入口；有足夠章節作答資料後再設計跨章節複習與排程。
P2：可公開作品集入口、跨裝置同步，依確認後的使用情境設計。
本版不做帳號、排行榜、影音生成、網站內 AI 教練或雲端資料庫。
