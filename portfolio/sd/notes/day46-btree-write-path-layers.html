B-tree 寫入路徑

讀完這頁你能：分清 metric / series / sample，並指著圖講一筆 INSERT 為什麼貴。

L0 一張圖 讀 1 分鐘

B-tree 像一座依名字排好的檔案櫃：每張新紙條都要走到它專屬的抽屜。

左邊是今天要懂的。右邊只是預告：不必插回排序位置，寫入就便宜。

L1 第一性原理 讀 3 分鐘

限制有兩個：寫入量極大，而 RAM 放不下所有 page。先分清計量單位。

Metric 是量測的名字。Metric + 一組 label 才是一條 series。Sample 是 series 上的一個資料點。

單位範例本題數量
metriccpu_usage沒給，也不需要
seriescpu_usage{host=h1,core=1}15M 條
sample(t=30, 71.2)1M 個/秒

10% 是教學假設，不是量測值。換更快的 disk 只會把牆往後推，寫入位置依然分散。

L2 機制 讀 5 分鐘

對，每筆 INSERT 都從 root 走到 leaf。走路本身便宜，貴的是 leaf 不在 RAM。

Leaf page 是最底層真正放資料的小塊，InnoDB 預設 16 KB。上層 page 常被讀，通常都留在 RAM。

最後把 15M 條 series 放回來。同一秒的 sample 分別屬於不同 series，所以散在整顆 disk：

我錯在這：我以為 1M samples/s 集中在少數 page。Key 開頭是 series，所以不同 series 分在不同位置，寫入是散開的。

之後再看：把 buffer pool 開大就解決了嗎？

每條 series 最新的那塊 leaf page 都得留在 RAM，才能避開 miss。長期運作下每條 series 大約佔一塊，15M × 16 KB = 240 GB，而且這只是最新資料。Batch INSERT 可以合併 commit，但資料位置依然分散。
