RBAC 動詞陷阱

客戶說「我們明明給了 pod 讀取權限」—— 而 CI 還是吃 403。他沒說謊,是因為人腦的「讀取」跟 RBAC 的動詞不是同一套詞彙。

證物

403 訊息本身就是完整診斷

$ kubectl get pods -n rbac-lab --as=$SA
Error from server (Forbidden): pods is forbidden:
User "system:serviceaccount:rbac-lab:ci-reader"
cannot list resource "pods" in API group ""
in the namespace "rbac-lab"

四要素全寫在裡面 —— 誰 · 動詞 · 名詞 · 在哪。這串 username 不是設計給你手打的,是給你選取、貼上去重現的。

Role 裡寫的是 verbs: ["get"]。訊息要的是 list。

主秀

動詞由請求的形狀決定,不是由指令的名字

kubectl get pods
→
list
複數、沒指定名字
kubectl get pod my-app-7d9f
→
get
指定了物件名字
kubectl get pods --watch
→
watch
第三個獨立動詞
封印句 kubectl get 這個指令名字騙人。有物件名字 = get,沒名字 = list,加 --watch = watch。

為什麼 watch 要獨立成一個動詞: list 是一次性快照,拿完就關;watch 開的是一條長連線,API Server 會把之後所有變更持續推給你。資源成本和外洩風險完全不同 —— 給了 watch 等於給對方一條常駐監聽通道。k8s 不讓你「順便」拿到它。

所以唯讀角色的業界慣用寫法永遠是三件套:verbs: ["get", "list", "watch"]

顧問層 進場問「你們給了哪幾個 verb」,不要接受「唯讀」這種形容詞。
工具

403 三段鏈,一發指令看完

  1. SA 存在嗎 —— 身分在不在
  2. binding 綁對了嗎 —— 綁了什麼、綁在哪個 ns
  3. Role 定義含這個 verb + resource 嗎 —— 動詞給齊了沒
$ SA=system:serviceaccount:ci:deployer
$ kubectl auth can-i --list -n payments --as=$SA

--as 裡的 ns 是 SA 住的地方;-n 是 要查的地方。兩個常常不一樣,而 403 訊息裡兩個都寫好了。

--list 的畫面斷在哪下一發
只剩噪音,一個 resource 都沒有 binding 完全沒生效
段 1–2		 get rolebinding -A -o wide
有東西,但缺這個 resource 權限沒涵蓋到它
段 2–3		 get rolebinding -n X -o wide
有這個 resource,但動詞不對 Role 定義少動詞
段 3		 describe role

兩個讀法: 不加 --as,問的是你自己。Non-Resource URLs 那一大坨(/healthz、selfsubject*)是每個通過 authn 的身分都自動有的 discovery 權限,不是你給的 —— 直接跳過,只看有 resource 名字的那幾行。

為什麼後兩種的下一發都是 get rolebinding: 「權限沒涵蓋」可能是 Role 漏寫,也可能是有一個 Role 寫對了但沒綁上去。--list 只看得到聯集的結果,分不出這兩者。

本堂最值錢的一條 · 跨主題通用

成功訊息不保證你以為的那件事發生了

同一堂課,三次撞到同一個形狀 —— 指令沒報錯,但沒做到你以為的事。

01
No resources found in ALL namespace.
以為查了所有 namespace。kubectl 真的去找了一個叫 ALL 的 namespace。 正解是 -A。
02
No resources found in rbac-lab namespace.
以為 impersonation 測試通過。$SA 是空的,--as= 沒送出去,你是用 admin 身分查的。
03
role.rbac.../pod-reader patched (no change)
以為沒改到。describe 驗出來其實已經改成 [get list watch]。 訊息誤導。

而 01 和 02 印出來的是同一句話。

No resources found in rbac-lab namespace.
✗impersonation 根本沒生效 —— 你在用 admin 查一個空 namespace。
No resources found in rbac-lab namespace.
✓權限正確、ns 裡真的沒有 Pod。
封印句 k8s 的成功訊息不保證你以為的那件事發生了。輸出跟預期不符時,先確認儀器沒壞,再懷疑機制。

資淺的人看到怪輸出開始改 YAML。資深的人先確認儀器沒壞。
