Layer 0 · 一張圖analogy

Layer 1 · 第一性原理why it must exist

限制：資訊頻寬。45 分鐘、只有語音，面試官要從這裡推斷你在 production 凌晨三點會怎麼做。他能用的證據只有你說出口的東西。

這條限制直接打在你最久的 pattern 卡上（見最後一節）。P6 的主要工作不是補知識，是補「把知識說出口」這一步。

Layer 2 · 機制three answer engines

incident round：expected behavior loop

system design round（k8s 交集題）
  1. 需求與規模：用數字問（QPS、資料量、租戶數）
  2. 估算：一頁紙算 node 數、儲存量
  3. 架構圖：先畫最簡單能跑的
  4. 深入一個瓶頸：選你最懂的（網路、權限、有狀態）
  5. 故障模式：AZ 掛、控制面掛、升級
behavioral round（STAR）
  1. Situation：一句話，有數字
  2. Task：你負責什麼（不是團隊）
  3. Action：佔一半時間，講判斷和取捨，回注 P0–P5 的機制
  4. Result：量化；加一句學到什麼

提煉門檻：衝突壓力 / 自己的判斷 / 可量化結果，三項佔兩項。

Layer 6 · 面試現場的失誤how it breaks

空白頁凍住

先說出 loop 的第一格：「Let me first clarify the blast radius.」說出框架本身就是訊號，也給自己時間。

只給結論

面試官連問兩次「why」就是警訊。每個答案強制套句型：「我看的是 X，因為 Y」。

跳層

答 RBAC 題卻講 NetworkPolicy；問跨 node 卻查 iptables。先問自己：這題的執行體在哪一層？

被同事誘答牽著走

run sheet 一定埋一個「重啟 X 吧」。用一個便宜的驗證擋下，不是用「我覺得不是」。

Layer 7 · 模擬題run sheet A

「14:20 on a weekday. Calls from checkout-api to payment-svc (ClusterIP, 6 pods) fail intermittently, roughly 1 in 10 new requests time out. Started 30 minutes ago. No deploys today. Where do you start?」

先自己講一遍，再打開。

L4 回答

「先 kubectl get pods 看 Pod 健康嗎，再看 logs。可能是 DNS，可以重啟 CoreDNS 試試。」

跳過 clarify；接受了誘答；沒有層的概念。

L6 回答

「Before touching anything: is it only payment-svc or other services too? Is it new connections only, or existing ones as well? Timeout or connection refused? And what changed in the last hour besides deploys, like cron jobs or traffic?」

「Hypotheses by layer, cheapest first: endpoints and probes, DNS, kube-proxy rules, then the node kernel. I'd check endpoints and run an FQDN nslookup from an affected pod. If both are clean, the Kubernetes object layer is healthy, and I need to go below what kubectl can see.」

「On the node: dmesg for nf_conntrack: table full, and compare nf_conntrack_count to nf_conntrack_max. New connections failing while established ones keep working is exactly the conntrack-full signature.」

「Mitigate: throttle the batch job that started 40 minutes ago. Raising the max is a stopgap. Prevent: alert on count/max above 80% from node-exporter, and give batch jobs a connection budget or dedicated nodes.」

這題的每一步都是你 P2a 親手做過的：謎題 C（conntrack）、DNS 排障第一刀（FQDN 二分）、s9 的 kubectl get conntrack 坑。
