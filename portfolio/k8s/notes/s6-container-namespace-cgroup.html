容器是什麼

容器不是小 VM，是一個被 kernel 加了幾種屬性的普通 process。這一頁把那幾種屬性一個一個拆開：namespace 改「看得到什麼」，cgroup 改「能用多少」，UID 決定「你是誰」，而這三件事互相獨立。

Layer 0 · 一張圖analogy

Layer 1 · 第一性原理why not VMs

限制：每台 VM 要多帶一份 OS kernel 和記憶體，開機是秒到分鐘級。一台 node 想跑 50 個 app，用 VM 就是 50 份 kernel。kernel 本來就會管 process，只要讓它對每個 process 給不同的「視野」和「額度」，就能在一份 kernel 裡隔開它們。

代價寫在圖上：右邊所有 process 共用那一條 kernel。kernel 有漏洞，所有容器一起暴露；container 裡的 root 在 kernel 眼中也是 UID 0。

兩道門：看不看得到 vs 准不准

UID 0 · 沒翻牆

讀 node 的 /etc/shadow：讀不到。門 1（mnt ns）根本看不到那個檔案。

UID 0 · 翻牆了

讀得到。門 1 沒了，門 2 只看 UID，0 什麼都准。這就是 root 的危險。

UID 1000 · 沒翻牆

讀不到（門 1）。

UID 1000 · 翻牆了

讀不到（門 2：shadow 只有 root 能讀）。runAsNonRoot 只改變這一格。

container 的檔案系統是 overlayfs：image 的唯讀層（lowerdir）加上一層可寫層（upperdir），upperdir 在 node 的磁碟上，跟著 container 的生命走（P2b C-1）。

Layer 6 · 故障與 on-callhow it breaks

container escape

例：runc CVE-2019-5736，container 內的 root 覆寫 node 上的 runc binary。只能等 patch；能做的是 non-root + 少給 capabilities，讓翻牆後拿到的身分沒用。

看得到不該看的

Pod 設了 hostPID: true 或 hostNetwork: true，等於把那個 namespace 拿掉。PSS baseline 就會擋。

container 內看到 node 全部 CPU

/proc/cpuinfo、free 不受 cgroup 影響，app 照 node 規格開 thread pool 或 heap。要讀 cgroup 檔案，不是 /proc。

debug 進不去

distroless image 沒 shell。用 kubectl debug 掛 ephemeral container 進同一個 Pod 的 namespace。

Layer 7 · 面試interview

「What actually isolates two containers on the same node, and why do security teams still care whether a container runs as root?」
L4 回答

「namespace 和 cgroup。root 比較危險，所以要用 non-root。」

名詞對，「為什麼危險」沒講出機制。

L6 回答

「容器就是 process 加上三件獨立的東西：namespace 決定看得到什麼，cgroup 決定能用多少，UID 決定 kernel 認為你是誰。前兩者是隔離，第三個沒被隔離：預設沒開 user namespace，所以容器裡的 root 在 node kernel 眼中就是 UID 0。」

「所以要分兩道門：沒翻牆時，mount namespace 讓它看不到 node 的檔案，root 或不是 root 沒差；翻牆後（kernel 或 runtime 漏洞，例如 runc CVE-2019-5736），只剩 UID 這道門，root 就什麼都能做。non-root 是為了『假設已被攻破』那個情境縮小損害。」

「實作：image 用非 root user、PSS restricted、drop ALL capabilities、seccomp RuntimeDefault；不信任的 workload 開 user namespace、或用 gVisor / Fargate 這種有獨立 kernel 的方案。」

L6 多了：把 UID 獨立出來講、兩道門的四格、一個真實 CVE、按信任程度分級的對策。
